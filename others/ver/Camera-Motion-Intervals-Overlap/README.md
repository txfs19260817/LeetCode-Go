# Camera Motion Intervals Overlap

## 题目描述
给定摄像头采样数据，每个元素为 `[timestamp, motion_level]`。

1. 单摄像头：给定 `threshold`，当 `motion_level >= threshold`（或严格大于）时视为运动中，输出连续运动区间 `[start, end]`。
2. 多摄像头：先分别求每个摄像头的运动区间，再求“所有摄像头同时在运动中”的公共区间。

## 解法思路
- 单摄像头使用一次线性扫描的状态机：
  - 进入运动状态时记录 `start`
  - 运动持续时更新 `end`
  - 退出运动状态时落盘区间
- 多摄像头使用区间交集：
  - 先得到每个摄像头的区间列表
  - 两两用双指针求交集，迭代到最终结果
  - 先从区间数较少的摄像头开始可减少中间结果规模

## 算法步骤
1. 对每个摄像头样本按时间戳排序（若输入天然有序可省略）。
2. 扫描样本构造运动区间列表。
3. 对多摄像头场景，将所有区间列表按长度升序。
4. 用双指针函数反复求两个区间列表的交集，直到处理完所有摄像头或交集为空。

## 复杂度分析
- 单摄像头：
  - 时间：`O(n log n)`（含排序）；若已按时间有序则 `O(n)`
  - 空间：`O(k)`，`k` 为输出区间数量
- 多摄像头：
  - 时间：`sum(O(ni log ni)) +` 若干次线性区间交集
  - 空间：与中间交集区间数量相关

## 边界与易错点
- 空输入应返回空区间列表。
- 注意阈值比较规则：`>= threshold` 与 `> threshold` 结果不同。
- 只有一个采样点也可能形成合法区间（如 `[36, 36]`）。
- 如果输入未排序，先排序再扫描，否则区间会错误。

## 示例
```text
Input:
vector = [[1, 0.4], [5, 0.2], [11, 0.9], [15, 0.9], [17, 0.8], [25, 0.5], [27, 0.8], [36, 0.9]]
threshold = 0.8

Output:
[[11, 17], [27, 36]]
```
