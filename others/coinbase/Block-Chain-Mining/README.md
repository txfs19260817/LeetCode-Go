# Block Chain Mining

给定一个 `blockSize` 和一组交易 `transactions`，每个交易包含：

- `id`
- `size`
- `fee`
- `parentId`（主问题可忽略，Follow-up 使用）

## 主问题

每个交易会占用 `size` 的区块空间，并带来 `fee` 收益。  
在区块容量限制内，如何尽量提高总收益。

说明：

- 理论最优是 0/1 Knapsack。
- 面试中常追问更高性能思路，可用 `fee / size` 做贪心近似。

## Follow-up

交易之间可能存在父子关系。  
要 mint 子交易，父交易必须在同一个 block 内。

并且在如下结构：

- `1 -> 2 -> 3`
- `1 -> 2 -> 4`

不能同时 mint `3` 和 `4`（二者共享同一个父链，视为同一组内互斥分支），只能选其中一个分支。

因此可以把每个根交易及其后代看作一个 group，在 group 内选一条路径，再在总容量约束下做全局选择，最大化收益。
